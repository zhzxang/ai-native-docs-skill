# 历史文档迁移

迁移是最小初始化后的独立动作。用户仅要求初始化时先完成 [ai-docs-init](../ai-docs-init/SKILL.md)，再询问是否迁移和范围；已有明确授权的迁移范围直接执行。没有文档只有代码时优先使用 [ai-docs-sync](../ai-docs-sync/SKILL.md)。

## 分类与迁移计划

先从同版本 [ai-docs-check](../ai-docs-check/SKILL.md) 公共资源读取 `writing-policy.md`、`collections.json`、`conventions.md`、相关类型模板及目标配置。阅读选定旧文档和入链，判断独立对象、分类、唯一来源、状态与批准映射；脚本不做语义分类。已有对象先更新，无法确认映射时保留原文，不制造第二份权威正文。

工具参数、映射格式与支持范围见 [migration.md](references/migration.md)。使用独立 `scripts/migrate.py` 盘点、预览并应用同一计划；默认资源是相邻 ai-docs-check 的 `assets/templates`，不同位置用 `--source /匹配资源根`。

脚本负责保留全文与元数据、类型 meta 校验、紧凑或展开布局、入出链与附件定位、薄跳转入口、哈希复验、锁与失败回滚。计划保存在目标之外，应用前审阅实际内容和映射。不支持或有歧义的旧格式明确阻断该项，不能用重写摘要代替完整迁移。

四个 README/AGENTS 协议入口保留，不支持整文件迁移。入口中的业务对象须在明确范围内提取并保全事实，不能把托管入口替换为跳转页。

## 历史事实与完成条件

保留稳定 ID、完整正文、状态、版本、批准、核验、附件和替代关系。已有元数据不可用新草稿覆盖；无元数据且有效性未经确认的材料使用 draft，未知字段按 schema 留 null。任务 `state`、发布 `release_state` 等不能为通过格式校验而猜测。

最终每个对象只有一个可编辑正文来源；旧路径可保留 `doc-redirect` 薄入口和旧锚点。修复仓库相关链接，外部入链无法自动更新时报告待处理项。检查前后基线、真实源内容与迁移映射，区分本次错误和历史未验证范围。格式通过不证明批准或分类正确，未迁移范围仍保留原位置并准确报告。
