# 变更影响检查

这是按变更触发的检查表，不要求每次修改都更新所有文档。先识别影响，再核验对应权威来源；无影响时明确记录理由，不为满足形式随便改日期或文字。

所有被触发的文档写入都先读取 `writing-policy.md` 和 `collections.json`，查找已有同主题条目后再新增；研究、反馈、成本、运行记录和交接也适用。以逻辑类别定位，不假定集合已是目录。原对象增加规则、验收、证据或分析不增加条目数。

| 变更 | 要检查的知识 / 配置 | 验证与交付影响 |
|---|---|---|
| 用户可见功能 | 功能、流程、页面、FAQ | AC、回归、Changelog |
| API 或事件 | 契约来源、错误语义、调用方 | 契约一致性、兼容性、消费者测试 |
| 数据结构 | 实体语义、迁移、生命周期 | 完整性、兼容窗口、恢复或前向修复 |
| 环境变量 | 配置组、校验定义、安全示例、部署注入 | 缺失/非法配置行为、凭据隔离 |
| 套餐与价格 | 定价版本、权益、退款、FAQ、展示 | sandbox 计费、权益测试、批准与生效 |
| 数据收集 | 事件、指标、用途、保留、第三方 | 数据质量、删除/访问、隐私文本核验 |
| UI / 信息架构 | 页面、流程、组件、Tokens、资产 | 视觉、键盘、状态、导航检查 |
| 新外部服务 | 架构、服务、配置、成本、安全 | 接入、故障、退出与数据边界 |
| 部署变化 | 部署程序、环境、服务、发布检查 | 工件、健康、迁移、恢复验证 |
| 权限或安全变化 | 权限、控制、威胁模型、密钥 | 允许/拒绝场景、受保护审批 |
| 重要技术取舍 | ADR、架构、模块说明 | 约束检查、迁移与例外 |
| 实际代码路径变化 | project-map.json、命令 cwd、必要引用 | 定位与启动核验，不改业务语义 |
| 任务完成 | 唯一任务 state、验证报告、交接 | 是否合并/发布需单独确认 |
| 集合新增第 3 个独立条目 | 原聚合条目、元数据、入链、相对出链、锚点、路由、必要索引 | 完整迁移、ID 和证据保留、没有双份正文 |
| 分类或工具协议变化 | 写入协议、注册表、路由、模板和结构检查 | 明确变更范围；不以降低门禁通过本次任务 |

对于历史或原始证据，新增结论应回写到相应有效规范；不要只在日志中留下关键规则。批准、验证和真实外部执行是不同事件。
