# 工具入口适配

## 共享正文，薄入口
本套件以根 `AGENTS.md` 保存共享执行约定。AGENTS.md 是公开格式，但文件发现、作用域和组合行为依客户端而异；必须在实际工具和版本上验证。

Codex 的发现链与启动目录和配置有关，不保证从仓库根启动就预先读取所有子目录规则。Claude Code 可通过 CLAUDE.md 的导入机制引入根 AGENTS.md；导入不是按需加载整套文档的方法。Copilot 在不同功能中支持的指令文件和组合规则也不同。

## 安装方式
适配模板位于 Skill 资源根的 `docs/_templates/reference/automation/adapters/`。只有在你的客户端需要时才复制薄入口到对应发现位置，通用规则继续从匹配版本的 Skill 读取。不要维护多份独立的长期规则，不要把整个 docs 通过导入放进启动上下文。

复制 Claude 入口模板到根目录后，`@AGENTS.md` 才相对于该位置生效；模板在 docs 中时不应被当作已安装入口。Copilot 模板中的文字引用不是平台级导入，必须通过实际任务检查是否加载并遵循共享正文。

## Skills 与普通工作流
参考流程位于 Skill 资源根的 `docs/_templates/reference/automation/workflows/`，采用后的项目操作文档属于 `workflow` 集合，按第三条展开协议存储；无内容不预建目录。普通文档不会因目录名字自动成为 Skills。只有真正反复复用且值得封装的流程才包装成 Skill。Skill 规范定义 name、description、SKILL.md 及渐进式资源加载；发现目录仍依赖客户端。

未采用的 Skill 参考集中在资源根的 `docs/_templates/reference/automation/skills/`，与提供公共文档协议的 `ai-docs-check` Skill 区分；参考文件未安装、没有执行权限，也不包含生产密钥。采用前调整触发描述、引用路径、允许工具和执行环境。所有客户端根入口必须明确定位匹配版本的资源并引导读取，不依赖自动触发，不将某台机器绝对路径写入项目。

## 验证
让客户端报告实际加载的指令来源；在根与一个有特殊规则的目录分别进行低风险测试；检查是否存在冲突、重复导入或过量上下文。升级客户端后重做关键加载验证。

权威参考及核验日期见 [来源说明](sources.md)。
