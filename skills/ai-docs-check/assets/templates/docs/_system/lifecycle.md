# 增长、分页、替代与归档

## 有界摘要与按需集合
有边界的当前摘要原地维护，例如项目概述、架构总览、测试策略和安全基线；有确认内容时才创建，不追加日记或版本清单。持续增长的事项使用固定逻辑集合，物理布局按 [writing-policy.md](writing-policy.md) 决定：无内容不建壳；1–2 个独立条目在 `<base_path>.md`；第 3 个独立条目展开为 `<base_path>/`；展开后每条目一个文件。

首次展开以独立对象计数，不按标题、段落、时间段、文件长度或修改次数猜测。已展开后条目减少不自动收拢，避免路径反复变化。改变分类、阈值或进行存量收拢须是有明确范围的独立整理，普通写入不附带这些副作用。

## README 也不能无限增长
集合不默认创建 README、index 或 overview。确需入口时只维护一个薄导航，已有定位足够时不增加。需要完整清单时由 `docctl.py index` 按需输出到 `_generated/indexes/<type>/page-NNN.md`，机器目录写到 `_generated/catalog/<type>/page-NNN.json`；紧凑与展开布局都按独立条目索引并带稳定锚点。每页最多 40 条；索引不拥有独立事实或任务状态。

根导航按任务和领域列目录，不列每一个需求。检索时优先查标题和摘要，再读命中文件，不默认读生成的全库索引。

## 第三条迁移
同一未展开集合写入第 3 个可以独立命名、检索和维护的条目时，迁移旧条目并新增第三条。保留 ID、完整元数据、状态、范围、证据和附件关系；元数据从逐条 `doc-meta` 转换为 front matter，内容标题转换为独立文件层级，显式小写 ID 锚点保留。

稳定 ID 不会自动修复 Markdown 链接。修复旧聚合路径的入链、搬迁后的相对出链、锚点及必要路由和索引，在同一可审查变更的最终检查点验证。完成后删除旧聚合正文；外部旧链接确实无法立即修改时可保留带 `<!-- doc-redirect -->` 标记的薄跳转页，保留旧 ID 锚点及新入口，但不得保留正文、逐条元数据或把它当可编辑集合源。

聚合与目录同时保存正文、丢失条目元数据或引用修复未完成时不能宣称迁移完成。复杂功能可以有必要附录，但摘要须说明哪些附录在何种任务下必读；增加验收条件或附录不会自动增加独立功能数。

## 计划、日志、发布
任务条目保存范围、验收和唯一状态；复杂计划保存当前推进结构及唯一交接摘要。只有需要持久化的会话或工作窗口才形成独立日志条目，不强制归档每次聊天。计划更新当前推进结构，不无限追加完整会话历史。发布按版本或发布事件形成独立条目，日志和发布集合也遵守第三条展开，不维护无限增长的根 CHANGELOG 文件。

## 历史版本
ADR、定价和已发布政策保留历史内容，用状态、适用区间和替代关系退出当前视图，不静默重写理由或生效规则。集合首次展开遵守上述完整迁移并保留引用映射；其后尽量保留原路径。需要物理归档时，先登记 `archive-record`，记录映射并更新引用；必要时保留简短跳转说明，归档位置只在实际需要时创建。

## 新鲜度
变更关联模块、来源失效、外部价格变化、适用版本变化时触发重新核验。不得通过批量刷新日期制造“已核验”。某些时间敏感来源需在任务执行时重新查询；采集时间只是历史记录。

## 生成物
生成索引可删除后重建，不手工更改条目状态。运行生成工具不会批准草稿。保留生成工具与规则的版本，CI 可检查重建后是否存在未提交差异。语义准确性、外部链接可用性和生产一致性仍需相应检查。
