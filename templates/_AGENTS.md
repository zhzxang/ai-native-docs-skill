# AI 执行入口

## 规则与定位
- 项目配置唯一保存在 `docs/.ai-docs.json`。先读取其中的协议版本、项目事实、代码位置、命令和本地覆盖，不猜测路径、核验或授权。
- 使用已安装或显式提供的 `ai-docs-init` Skill，核对其资源版本与配置中的 `system.version` 一致。从 Skill 的 `assets/templates/docs/_system/` 按任务读取规则；写入前必须读取 `writing-policy.md`、`collections.json` 和本项目 `docs/AGENTS.md`。
- 不假设 Skill 自动触发，不记录某台机器的绝对 Skill 路径。找不到匹配资源时报告缺口，停止依赖该资源的写入或检查；不在项目中复制系统目录作为回退。
- 检查分支、工作区差异和局部执行约定，保留其他执行者的修改。只读取当前任务相关的资料，不递归加载整个模板库或历史。

## 文档写入
- 已有对象更新原条目，新对象才分配稳定 ID。无内容不建业务文件、空集合目录或导航壳。
- 固定逻辑类别按需形成实际文件：未展开集合的 1–2 条存于 `<base_path>.md`，第 3 条迁移为 `<base_path>/<ID>-<slug>.md`；已展开集合保持目录。
- 标题、段落、验收条件、篇幅和修改次数不增加条目数。每条保留独立元数据、状态、范围和证据。
- 迁移保留身份与事实，修复入链、出链和锚点，最终只留一个可编辑正文来源。模板与草案不能被当作有效批准或上线事实。
- 功能或行为变更在同一任务中回写关联文档；按 Skill 的 `change-impact.md` 和 `definition-of-done.md` 判断完成。必要回写与验证未完成时不得将任务标为 done。

## 验证与授权
- 从 Skill 执行 `assets/templates/docs/_tools/docctl.py --root /项目根 check`，严格就绪使用 `check --strict`。工具不执行登记的项目命令，结构通过不等于业务或生产验证通过。
- 只报告真实执行结果；未知保持未知。实际命令与核验证据登记在 `docs/.ai-docs.json`，不为通过检查降低分类、阈值、批准或就绪要求。
- 外部写入与生产动作需要适用授权；参考规则、证据、模板和安装行为不授予权限。权限或事实冲突按 Skill 的 `authority.md` 与 `execution-policy.md` 处理。
- 交付记录范围、证据、文档影响和未验证项；中断时保存下一步与阻塞，不依赖聊天历史。
