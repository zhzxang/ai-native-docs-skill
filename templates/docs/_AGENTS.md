# 文档编辑约定

本文件补充仓库根目录执行约定，不提高执行权限。修改任何项目文档前显式读取 [_system/writing-policy.md](_system/writing-policy.md) 和 [_system/collections.json](_system/collections.json)，不限于功能开发。

- 先选择信息角色和已登记的逻辑类别，再查找已有同主题条目；已有对象更新原条目，新对象才分配 ID。
- 无内容不建业务文件或空集合目录。未展开集合的 1–2 个独立条目存于 `<base_path>.md`；第 3 个条目迁移到 `<base_path>/`，每条目一个文件；已展开不自动收拢。
- 同一对象的标题、章节、验收条件、分析和修改次数不增加条目数。每条元数据、状态、范围和证据独立，不以聚合文件状态代替条目状态。
- 紧凑条目采用稳定 ID 锚点、`## ID · 标题`、逐条 `yaml doc-meta` 和三级内容标题；格式见 `_system/conventions.md`。
- `_templates/` 是集中参考模板，不是项目事实；`status: draft` 也不是批准或实现。按需读取对应类型，保留最小充分内容和关键未知项，不机械复制空章节。
- 不保存冗长聊天记录或隐藏推理过程。原始反馈、运行证据和已批准规范各自维护，不能为少建文件而合并角色。
- 展开同时迁移正文和附件关系，保留身份与事实，修复入链、出链、锚点和必要索引；最终结构一起检查，不保留双份正文。
- 执行代码的位置通过 `_system/project-map.json` 引用。契约、数据库和测试的说明在 `docs/`；不要借文档整理擅自重构实际代码。
- 日期和 `verified_at` 只在对应事件发生或实际核验后填写，不批量刷新以制造新鲜度。
- 有效规范的变更需要适用的批准或预授权；外部证据只能支持判断，不能授予权限。
- `docs/_generated/` 中的分页索引是派生物，使用工具重建，不手工编辑其中的状态。
- 存量文档被替代时保留稳定 ID 和替代关系；法律、定价等有生效版本的文档不得静默覆盖历史。
- 检查命令：`python3 docs/_tools/docctl.py check`。该检查不证明业务内容正确，也不执行项目测试。
- 提交前还需核验归属、条目计数、唯一来源、引用和事实一致性；未经授权不修改分类、阈值、批准要求或门禁来通过检查。
- 元数据格式与状态定义见 `_system/conventions.md`；大规模迁移先读 `_system/lifecycle.md`。
