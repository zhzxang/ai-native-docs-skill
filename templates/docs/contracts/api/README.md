# API 契约说明

## 职责与边界
一个 API 操作或内聚接口组的业务语义和兼容约束。

记录单位：**每个操作或不能合理拆开的内聚接口组一份文件**。本文件只维护集合说明、查找方式和稳定入口，不持续追加全部条目。

## 创建与查找
模板：[完整条目模板](_template.md)。从仓库根目录运行：

```bash
python3 docs/_tools/docctl.py new api API-001 example --title "填写具体标题"
python3 docs/_tools/docctl.py find --type api --status active --limit 20
```

命令仅创建草稿，不批准内容、不执行项目命令、不授予外部操作权限。没有 Python 环境时，可手动复制 `_template.md`，更换 ID 和标题，并将 `status` 改为 `draft`。

命名建议：`API-001-short-slug.md`；按时间增长的集合可逐步使用年份子目录。ID 必须在整个文档库中唯一，移动文件不得改变 ID。

## 读取方式
先按任务、ID、标题或摘要搜索，读取命中的条目；仅在任务需要时展开其关联文档。不存在有效条目时，应记录知识缺口，不把模板内容或草稿当作项目事实。

## 权威与更新
相关规范、实现、证据或适用条件变化时，重新核验受影响条目。[命名、元数据与状态规则](../../_system/conventions.md)定义文档状态；实现事实和外部系统位置见[真实代码和外部来源映射](../../_system/project-map.json)。条目内的 `verified_at` 只在实际核验并记录证据后填写。

## 增长与归档
不要把新条目追加进本 README 或 `_template.md`。索引由工具按页生成；历史内容通过状态、替代关系和适用版本区分。归档前检查入链，必要时在原路径保留指向新位置的说明。
