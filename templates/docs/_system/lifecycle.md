# 增长、分页、替代与归档

## 两种存储方式
有边界的当前摘要原地维护，例如项目概述、架构总览、测试策略和安全基线；这些文件不追加日记或版本清单。持续增长的事项一条一文件，例如需求、任务、ADR、成本月份、版本发布、反馈、日志和 FAQ。

## README 也不能无限增长
集合 README 只维护稳定说明与查找入口。完整条目清单由 `docctl.py index` 输出到 `_generated/indexes/<type>/page-NNN.md`，机器目录写到 `_generated/catalog/<type>/page-NNN.json`。每页最多 40 条；索引不拥有独立事实或任务状态。

根导航按任务和领域列目录，不列每一个需求。检索时优先查标题和摘要，再读命中文件，不默认读生成的全库索引。

## 拆分触发
一个文件开始承担多个独立问题、混合多个时间窗口或包含大量互不相关的条目时，拆成集合。不要机械按字数拆开必须共同理解的规则。复杂功能可拥有一个摘要和独立附录，但摘要应说明哪些附录在什么任务下必读。

## 计划、日志、发布
任务记录保存范围、验收和状态；复杂计划保存当前推进结构及唯一交接摘要；每次会话的客观经过进入独立日志。计划更新为当前状态，不无限追加完整会话历史。发布说明按版本拆分，不维护无限增长的根 CHANGELOG 文件。

## 历史版本
ADR、定价和已发布政策尽量保留原路径并用状态、适用区间和替代关系退出当前视图。此做法比随意移动更有利于稳定引用。需要物理归档时，先记录映射，更新入链；原路径留下简短跳转说明。归档目录按年份和原领域分区，一次迁移一份记录。

## 新鲜度
变更关联模块、来源失效、外部价格变化、适用版本变化时触发重新核验。不得通过批量刷新日期制造“已核验”。某些时间敏感来源需在任务执行时重新查询；采集时间只是历史记录。

## 生成物
生成索引可删除后重建，不手工更改条目状态。运行生成工具不会批准草稿。保留生成工具与规则的版本，CI 可检查重建后是否存在未提交差异。语义准确性、外部链接可用性和生产一致性仍需相应检查。
