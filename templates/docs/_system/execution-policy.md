# AI 执行授权与自治边界

> 此文件是保守的初始策略提案。模板安装本身不授予生产、资金、个人数据、账户管理或任何外部写入权限。项目负责人需要确认边界，并用实际运行环境落实。

## 默认启动模式
项目 `docs/.ai-docs.json` 的 `project.operating_mode` 默认为 `bootstrap`。在用户已授权的仓库范围内做只读盘点、草拟文档和验证模板工具；不把示例命令、未经核验的脚本或草稿政策当作执行许可。

## 权限分层
| 操作 | 条件 |
|---|---|
| 阅读已授权仓库、创建任务和草稿 | 当前请求明确包含该工作，且没有敏感数据越界 |
| 本地代码修改和无生产访问的测试 | 符合任务范围；命令与环境经过确认，受沙箱和资源限制 |
| 预发布部署或兼容性生产发布 | 明确授权或范围有限、有效的预授权；全部门禁满足 |
| 真实退款、生产删改、密钥轮换、调价、政策发布、批量外发 | 必须有相应的有效授权、执行范围与恢复/补救机制 |
| 变更权限和保护规则 | 独立的保护性变更，执行者不能自行授权或绕过 |

## 预授权至少包含
授权者、被授权主体、适用任务或操作、目标环境、允许的资源和数据范围、单次与累计预算、到期时间、最大重试次数、验证条件、失败恢复与撤销方法。执行前检查授权没有失效、撤销或被范围变化突破。

授权记录属于 `approval` 集合，按写入协议在 `docs/work/approvals.md` 或已展开的 `docs/work/approvals/` 保存；用注册表和定位工具查询，不预建空授权文件。但可验证的批准来源应留在访问控制可靠的系统。AI 自己写下“已批准”不构成批准。凭据最小化、受保护分支、CI 审批与网络边界应由工具环境落实。

## 停止与继续
缺授权时停止对应高风险动作，不阻塞仍在范围内的安全工作。连续失败、超预算、目标变化、异常数据访问或无法证明恢复安全时，记录证据与下一步，不通过降低测试要求完成任务。

## 并发执行
变更前检查工作区、任务认领和分支范围。不同 Agent 优先隔离工作树，合并由既定流程处理。发现文件冲突时不得覆盖他人改动。文档 ID 在分支上分配后仍需合并时检查唯一性。
